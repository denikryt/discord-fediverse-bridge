# Исправления Fluxer после CP034

Дата: 29 октября 2026 года. База: `1645689c63601ceea8b7ad98b2ab0a023b4da160` + CP001–CP034.

CP035–CP041 здесь обозначают согласованную исправляющую серию. Реальная приёмка Fluxer, ранее названная CP035 в исходном плане, остаётся отдельным этапом. Issue #12 не закрыта: Docker Compose и настоящий Fluxer-инстанс в этом окружении недоступны.

## Дополнительно подтверждённый дефект SIGTERM

До CP040 настоящий Uvicorn после SIGTERM закрывал HTTP, восстанавливал обработчик сигнала и повторно поднимал сигнал. Процесс завершался с `exitcode=-15` до вызова `Runtime.close()` и подтверждённого закрытия SQLite. Обычный успешный возврат одной задачи также не заставляет `asyncio.TaskGroup` отменить её бесконечного соседа.

Исправление оставляет обработку SIGTERM/SIGINT у `app.main()` до конца cleanup и использует внутренний сигнал завершения службы для присоединения соседа. При отмене HTTP явно выполняется его shutdown. Если присоединение HTTP не подтверждено, Runtime сохраняет owner и его ошибку, а успешный `Database.close()` сам по себе не разрешает снять блокировки. Это проверено реальными процессами, без Discord-сетевого соединения: заменена только внешняя SDK-граница.

### Ограничение Fedify

Штатный `npm test` доходит до 20 успешных security-тестов на Node 22.16.0, затем `tsx` не может создать Unix-сокет: `listen EPERM`. Перенос `TMPDIR` внутрь рабочего каталога не снимает запрет. Альтернативный `node --import tsx` выполняет 51 файл. Оставшийся `verify-env-loading.ts` сам запускает дочерний CLI `tsx` и встречает тот же запрет; тест не отключён и не изменён ради PASS.

На Node 22.13.1 security-тесты Fedify дополнительно встречают отсутствие `node:module.registerHooks`; на реально установленном Node 22.16.0 этот барьер отсутствует. Fluxer успешно проверен на обеих этих версиях Node 22. Эти ограничения не обходились изменением production транспорта или ослаблением security-тестов.

## Что остаётся проверить вне окружения

`dev/verify_fluxer_deployment.py` работает с явно выбранным изолированным Compose project и настоящими контейнерами. Он проверяет фактический shared network namespace, loopback-only bind RPC, отсутствие published RPC-порта, отдельный read-only token mount, отказ неаутентифицированных RPC/ingress, authenticated READY и bot identity, независимый restart sidecar, обратный порядок clean shutdown и доступность SQLite под обеими leases после остановки.

Эта программа здесь не запускалась на Docker. Opt-in pytest для неё отмечен SKIP при отсутствии заданной тестовой конфигурации. Наличие программы и статические YAML-тесты не означают прохождения B20/B21. Также требуется отдельное реальное действие Discord во время зависшего Fluxer: сохранность Python-процесса и HTTP health сами по себе не доказывают прогресс Discord-доставки.

Остаются настоящие серверные discovery/auth, forum Create с раздельными thread/starter ID, вложенные replies, tags/permissions, собственные Edit/Delete, Gateway Create/Update/Delete, reconnect/resume, потерянный REST-ответ и recovery. **Физические операции в production `main.ts` не включены; capabilities не повышены.** Запрет Fluxer→ActivityPub canonical publication до Issue #13 сохранён.

## Артефакты и воспроизведение

Каждый CP035–CP041 — отдельный инкрементальный patch поверх предыдущего. Итоговый ZIP содержит CP001–CP041 и `APPLY_ORDER.txt`. Применять следует к указанному исходному HEAD, по этому порядку. Итоговый архив проекта содержит весь checkpoint-код с незакоммиченными изменениями и `.git`; зависимости, временные базы и кэши не включены. Коммиты, push, merge и deployment не выполнялись.

Отдельный evidence ZIP содержит логи успешных и диагностических прогонов, JUnit, метаданные окружения, SHA256 артефактов и результаты replay. Финальное Git-дерево фиксируется в manifest этого архива, чтобы не создавать самоссылку внутри файла, входящего в проверяемое дерево.
